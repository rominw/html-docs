1. 全局图景:三个协议,三层地盘

它们不是竞争关系,而是分层互补——记住这张图,选型不迷路。

关键洞察:Modbus 管"设备怎么把数据交出来",OPC UA 管"数据是什么含义",MQTT 管"数据怎么穿过互联网到云上"——现场 / 控制 / 广域网,三个协议各守一层,共同构成现代工业物联网的骨干。

2. MQTT:为卫星链路而生的极简主义者

1999 年 IBM 监测油管:按字节计费、高延迟、常断链——一切设计皆源于此。

发布 / 订阅解耦

经 Broker 中转,发布者与订阅者互不相识;一对多分发、设备替换零改造。

2 字节固定头

对比 HTTP 动辄数百字节的头,报文开销极小;Topic 按 / 分层,+ 单层 # 多层通配。

为不可靠网络设计

QoS 分级确认、遗嘱消息感知掉线、保留消息补快照、心跳保活——断线恢复内建。

2.1 报文三层结构

固定头(2~5 字节)+ 可变头 + 载荷。剩余长度采用变长编码:每字节低 7 位有效,最高位为 1 表示有续字节,最多 4 字节(上限 256MB)。

CONNECT 报文实例(逐字节):
10 1d 00 04 4d 51 54 54 04 02 00 3c 00 11 72 61 77 ...
└类型1┘└长度┘└─ "MQTT" ─┘└级4┘└标志┘└KeepAlive┘└ ClientID ─┘
       29字节   协议名        3.1.1  CleanS  60秒

发送 SUBSCRIBE 时标志位固定 0010:82 0d 00 01 00 08 "test/raw" 00
                                     │  └PacketID=1    └请求QoS=0
                                     类型8+标志0010(协议强制,违反被踢)

PUBLISH 第一字节:0011 DUP QoS Retain → 30=QoS0 · 32=QoS1 · 34=QoS2

2.2 QoS 状态机:为什么 QoS 2 要四步

选型口诀:高频传感器流数据 QoS 0(丢了下条就来);一般业务 QoS 1 + 消费端幂等去重;计费与控制指令 QoS 2。QoS 1 快(2 次交互),QoS 2 用"两轮确认 + 去重状态表"换恰好一次。

2.3 会话、遗嘱与保留

遗嘱消息 LWT

连接时预先留言,异常掉线(未走 DISCONNECT)由 Broker 代发 offline——云端秒级感知设备断电。记得 retain=True,否则快照不更新。

保留消息 Retained

Broker 存最后一条,新订阅者零等待拿到快照——开关状态类数据标配。

会话 Session

CleanSession=0 时 Broker 攒着离线期间的 QoS≥1 消息,重连补发 = 离线消息队列;5.0 改为 Session Expiry Interval 细粒度控制。

3. Modbus:比 TCP/IP 还老的现场之王

1979 年 Modicon 为 PLC 而设计;简单到极致,才能活过 40 年。

3.1 数据模型:一切皆寄存器柜

抽屉宽度读写对应物理量文档惯用地址报文地址(0-based)
线圈 Coil1 bit读写继电器 / 阀门开关00001~文档地址 − 类型基数
(40001→0x0000)
两套基准不统一是现场第一大坑
离散输入 Discrete Input1 bit只读按钮 / 限位开关10001~
输入寄存器 Input Register16 bit只读传感器测量值30001~
保持寄存器 Holding Register16 bit读写设定值 / 参数40001~

3.2 功能码与异常响应

核心功能码(覆盖 90% 流量)

  • 01 读线圈 / 02 读离散输入 / 03 读保持寄存器 / 04 读输入寄存器
  • 05 写单线圈 / 06 写单保持寄存器
  • 0F 写多线圈 / 10 写多保持寄存器

异常 = 功能码 + 0x80

  • 异常码 01 非法功能 · 02 非法地址 · 03 非法数据 · 04 从站故障
  • 实测:读不存在地址返回 function_code=131(0x83=03+80),exception_code=2

3.3 RTU 帧 vs TCP 帧

字节序大坑:单寄存器协议规定大端,但 32 位值拆两个寄存器后顺序没人管——ABCD(大端)/ CDAB(字交换)/ BADC(字节交换)各厂不同,读出垃圾值先怀疑字节序,采集代码必须留重排开关。CRC 同理:pymodbus 返回"已交换可直接拼帧"的值,手写实现常返回寄存器自然值,对不上先看约定。

3.4 三种切帧策略(协议设计必杀题)

协议切帧依据权衡
MQTT固定头"剩余长度"(变长编码)省字节,解码稍复杂
Modbus TCPMBAP"长度"字段(定宽 2B)简单,多 2 字节开销
Modbus RTU3.5 字符时间的总线静默串口无长度前缀,靠时间切帧 → 对波特率与驱动延迟敏感
HTTP(对照)换行符(头)+ Content-Length(体)文本协议思路

4. OPC UA:带安全与语义的工业普通话

2008 年 OPC 基金会重造;IEC 62541 国际标准;传输的不是数据,是"知识"。

4.1 地址空间:带类型的节点图

八种节点类别(NodeClass)

  • Object / Variable / Method——实例层:设备、数据点、可调用函数(90% 数据交换走 Variable)
  • ObjectType / VariableType / DataType——类型层:可继承的模板(HasSubtype),像面向对象
  • ReferenceType / View——关系与视图
  • NodeId = 命名空间索引 + 标识符:ns=0 是规范定义的标准命名空间,ns=1+ 厂商自定义,互不冲突

配套规范(Companion Specs)

  • DI 设备集成基础 · PLCopen 控制逻辑 · PackML 包装机械 · Euromap 塑机 · MDIS 油气仪表
  • 符合同一配套规范的两家设备,SCADA 接入零配置——语义互操作的终极形态

4.2 订阅-通知:对轮询的降维打击

三层结构记牢:Subscription(订阅)→ MonitoredItem(监视项,可设采样间隔 / 死区 / 队列长度)→ Notification(带序号保证可靠)。推送 + 序号重传 = 兼得低延迟与可靠性。

4.3 安全五层 与 PubSub 扩展

安全内建,工业协议之最

  • ① SecureChannel:应用层握手协商对称密钥,每条消息加密 + 签名
  • ② 消息完整性:SHA 签名防篡改
  • ③ 应用认证:X.509 证书双向认证
  • ④ 用户认证:匿名 / 账号密码 / 证书 / LDAP
  • ⑤ 授权:按节点控制读写权限
  • 报文交互:HEL 握手 → OPN 开安全通道 → MSG 加密业务 → CLO 关闭;生产禁用 None 策略

PubSub(2015, Part 14)

  • 经典 C/S 订阅之外新增发布订阅模型
  • 底层可走 UDP 多播(TSN 场景)或消息代理(AMQP / Kafka / MQTT)
  • 典型架构:PLC --OPC UA-- 网关 --UA PubSub over MQTT-- 云
  • 语义模型(UA)× 云连接(MQTT)的联姻,现代工业物联网趋势

5. 三协议终局对比与选型

背下这张表,面试与选型双杀。

维度Modbus (1979)MQTT (1999)OPC UA (2008)
通信模型主从问答(请求/响应)发布/订阅(Broker 中转)C/S + 订阅推送(+PubSub)
数据语义无 —— 寄存器号,手册说了算无 —— topic 靠约定完整信息模型 类型/单位/关系/权限
安全无 裸奔 40 年TLS + 用户名密码(外挂)内建五层 加密+双向证书+授权
报文开销极小(8B 起)极小(2B 头)大(数百字节起)——安全与语义的代价
实现复杂度单片机可写嵌入式友好重,网关级起步
并发能力串口单主;TCP 靠事务ID天然一对多多客户端并发 + 订阅
典型位置现场设备 ↔ 网关/PLC网关 ↔ 云平台PLC/SCADA ↔ MES/上层
类比寄存器柜子广播电台会说话的百科全书

选设备侧

传感器 / 电表 / 变频器,看手册支持什么就凑什么——大概率 Modbus RTU;PLC 与 SCADA 对接优先 OPC UA。

选云侧

广域网、弱网、海量设备上报,选 MQTT(Broker 选 EMQX / Mosquitto);需要语义与历史数据再叠 OPC UA PubSub。

选中间

边缘网关做协议转换:南向 Modbus/OPC UA 采集,北向 MQTT 上云——三者在这张架构里各就其位,而不是三选一。

面试高频:① 为什么 TCP 可靠了还要 QoS?——TCP 是点到点(网卡到网卡),QoS 是端到端(应用到应用),接收进程崩溃时 TCP 已确认的数据照样丢。② MQTT 与 HTTP 区别?——发布订阅 vs 请求响应、2B 头 vs 数百字节头、双向长连接服务端可推。③ OPC UA 与 Modbus 本质区别?——自描述语义 + 内建安全。④ 40 年的 Modbus 为什么不死?——极简、免授权、任意单片机可实现、确定性轮询适配控制场景。
