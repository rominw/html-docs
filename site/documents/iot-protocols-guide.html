1. 先搞清楚:设备之间也要"说话"

工厂里的温度计、电表、机器人,是怎么把数字告诉电脑的?

想象一个工厂:几百个温度计、电表、电机、机器人,全都要把"我现在多少度""我用了多少电"告诉电脑;电脑也要反过来下命令:"停!""转快点!"

人和人说话要共同语言,设备和设备说话要"协议"(protocol)。协议就是一套规矩:消息长什么样、谁先说、说错了怎么办。这份文档讲工业界最常用的三种,它们性格完全不同:

Modbus = 点名提问

老师(电脑)点名:"3 号电表,报一下你的读数!"学生(设备)才能答一句。设备永远不主动说话。

MQTT = 广播电台

电台(服务器)只管按频道播消息;谁想听"天气频道"就调到那个频道。播的人和听的人互相不认识。

OPC UA = 自我介绍的贵宾

一进门就递上名片:"我是 3 号泵,我有温度(单位℃)和压力(单位 bar),会启动和停止两个动作。"

一句话总纲:三个协议不是三选一的对手,而是流水线上的三站——Modbus 负责从设备取数,OPC UA 负责让数好懂,MQTT 负责把数送到云端。接下来一章一个,慢慢看。

2. MQTT:广播电台式聊天

关键词只有三个:发布、订阅、频道(主题)。先看懂,再动手。

2.1 它为什么被发明(一个真实故事)

1999 年,IBM 的工程师要监控沙漠里的输油管道。传感器数据得靠卫星电话传回来——又贵、又慢、还老断线,发一条消息像寄一封很贵的信。于是他们设计了一个"抠门"到极致的协议 MQTT:消息能多短就多短,断了线能自动补发,设备掉线对方还能立刻知道。今天它成了物联网设备上网的第一选择。

2.2 三个关键词,用电台来记

发布 publish

把消息扔给电台。"我是 3 号温度计,我要播一条:25.3 度。"

频道 topic(主题)

消息上贴的标签,像电台频道:factory/line1/temperature(1 号产线的温度)。标签用 / 分层,像文件夹路径。

订阅 subscribe

调到某个频道收听。"我只听 1 号产线的一切"(factory/line1/#,# 是"后面全部"的通配符)。

最重要的一点:发消息的和收消息的互相不认识!发的人只管扔给电台(这个"电台"软件叫 Broker,常见的有 Mosquitto、EMQX),电台按标签分发给所有调了这个频道的人。好处:新增一个听众(比如手机 App),谁都不用改代码。

2.3 两个贴心功能(知道就行)

遗嘱:掉线自动广播

设备上线时跟电台约定好:"我要是突然断线,替我广播一句'3 号掉线了'"。这样设备一断电,后台立刻知道,而不是干等超时。

保留:新听众秒看最新值

电台把每个频道最后一条消息贴在公告栏。新听众一调频道,立刻看到最新值,而不用干等下一次播报。开关状态这类数据特别需要它。

2.4 动手玩:5 分钟发出你第一条 MQTT 消息

前提:电脑装了 Docker,并按 第 6 节把"电台"(Mosquitto)跑起来。然后:

第 1 步:开一个终端(PowerShell),输入下面这行,回车。它是"我要收听 classroom/seat1 频道"——

docker exec -it mosquitto mosquitto_sub -t "classroom/seat1" -v

看起来卡住不动?正常,它在等消息,别关。
第 2 步:再开一个终端,输入下面这行回车,它是"往 classroom/seat1 频道播一条消息"——

docker exec -it mosquitto mosquitto_pub -t "classroom/seat1" -m "你好,我是第一条消息"

第 3 步:回到第一个终端——消息出现了!你在两个窗口之间完成了一次"发布 → 电台 → 订阅"。

人话总结:MQTT = 有个电台(Broker),大家往频道(topic)里扔消息(publish)或调频道收听(subscribe),发和收的互相不认识。消息极短、省流量、天生适合"设备 → 云端"上报。

3. Modbus:老师点名式问答

比你家电脑还老 6 岁的协议,靠"简单粗暴"活到今天。

3.1 一条铁律:设备永远不主动说话

Modbus 诞生于 1979 年(比 Windows 还早 6 年)。当年设备都挂在一根共用的电线上,谁都能喊话就全乱了,所以定下铁律:一台"主站"(电脑)当老师,一群"从站"(电表、传感器)当学生;学生只有被点名才能回答,一次问答 = 读一个数,或写一个数。这个"傻"设计反而让它皮实到今天——几乎所有电表、变频器、PLC 都还认它。

3.2 设备内部:一个柜子四个抽屉

抽屉(行话叫"寄存器")存什么能读?能写?生活例子
开关开 / 关✔✔继电器、指示灯、阀门
只读开关开 / 关✔✘按钮被按了吗、门开了吗
只读数字数字✔✘温度读数、电压、电量
可写数字数字✔✔设定值:目标温度、运行频率

记两个就够入门:想读设备的数 → 开"只读数字"抽屉;想给设备下指令 → 开"可写数字"抽屉写个数(或开"开关"抽屉拨一下)。其他细节用到再查。

3.3 它的三个毛病(正是下一位出场的原因)

不会自我介绍

"1 号抽屉里的数字是温度还是压力?"设备不告诉你,得翻它家说明书,每家写得还不一样。

没有锁

插上网线,任何人都能读能写。在车间内网凑合,连到互联网就是裸奔。

要不停追问

"变了吗?""变了吗?"……老师得挨个点名问,数据变了也要等下一轮才被发现,又慢又费。

3.4 动手玩:10 分钟,假装自己是一台电表

前提:装好 Python,并 pip install pymodbus(只需做一次)。然后建两个文件:

文件 1:fake_meter.py —— 我是一台假电表(从站),肚子里放好了数:

from pymodbus.server import StartTcpServer
from pymodbus.simulator import SimDevice, SimData
from pymodbus.simulator.simutils import DataType

device = SimDevice(
    id=1,                                        # 我是 1 号设备
    simdata=(
        [SimData(address=0, values=[False] * 8, datatype=DataType.BITS)],      # 开关抽屉:8 个全关
        [SimData(address=0, values=[True, False], datatype=DataType.BITS, readonly=True)],  # 只读开关
        [SimData(address=0, values=[220, 50], datatype=DataType.REGISTERS)],   # 可写数字:设定值
        [SimData(address=0, values=[230, 49], datatype=DataType.REGISTERS, readonly=True)], # 只读数字:电压/频率
    ),
)
print("假电表已开机,等待点名… (按 Ctrl+C 关机)")
StartTcpServer(context=device, address=("127.0.0.1", 5020))

文件 2:read_meter.py —— 我是采集电脑(主站),来点名读数:

from pymodbus.client import ModbusTcpClient

client = ModbusTcpClient("127.0.0.1", port=5020)   # 找到那台电表
client.connect()

result = client.read_input_registers(address=0, count=2, device_id=1)  # 点名:1号,读2个"只读数字"
voltage, freq = result.registers                   # 拿到两个数
print("电压:", voltage, "V")
print("频率:", freq, "Hz")

client.close()

跑法:终端 1 执行 python fake_meter.py(电表开机);终端 2 执行 python read_meter.py(去读)。你会看到 电压: 230 V / 频率: 49 Hz——两个终端,一问一答,这就是 Modbus 的全部灵魂。

人话总结:Modbus = 老师点名,学生作答。设备是带四个抽屉的柜子,读数开"只读数字"抽屉,下指令写"可写数字"或"开关"。简单、老、遍地都是,但没说明、没锁、还得很勤快地问。

4. OPC UA:自带说明书的贵宾

Modbus 的三个毛病,它一个药方全治了。

4.1 对症下药

毛病:不会自我介绍

药:连上就能"浏览"它有什么数据——名字、单位、范围全都在,像设备自带一本目录。再也不用翻各家说明书。

毛病:没有锁

药:连接要验明正身(双方交换证书,像对接头暗号),消息全程加密,还能规定"这个数谁只许看不许改"。

毛病:要不停追问

药:改成"订阅"——你跟设备说"温度一变就告诉我",之后数据一变化,毫秒级主动推给你,不变不打扰。

4.2 核心概念:一棵带说明的目录树

4.3 动手玩(选做,前两个玩熟了再来)

前提:pip install asyncua。两个文件,跑法同 Modbus(终端 1 开服务器,终端 2 跑客户端)。

文件 1:ua_server.py —— 我是一台会自我介绍的设备,温度每 2 秒自己涨 0.5:

import asyncio
from asyncua import Server

async def main():
    server = Server()
    await server.init()
    server.set_endpoint("opc.tcp://127.0.0.1:4840")        # 我的门牌:本机 4840 端口
    idx = await server.register_namespace("myhome")        # 我的私有命名空间
    temp = await server.nodes.objects.add_variable(idx, "livingroom_temperature", 25.0)
    await server.start()                                  # 关键:真正开始监听端口
    print("OPC UA 设备已开机,温度每 2 秒涨 0.5 …")
    while True:
        await asyncio.sleep(2)
        await temp.write_value(await temp.read_value() + 0.5)

asyncio.run(main())

文件 2:ua_client.py —— 我订阅了温度,一变就打印:

import asyncio
from asyncua import Client

class 听通知的人:
    def datachange_notification(self, node, val, data):    # 数据一变,这个函数被自动调用
        print("温度变了!现在:", val)

async def main():
    async with Client("opc.tcp://127.0.0.1:4840") as client:
        idx = await client.get_namespace_index("myhome")
        temp = await client.nodes.objects.get_child([f"{idx}:livingroom_temperature"])
        print("当前温度:", await temp.read_value())        # 先读一次
        sub = await client.create_subscription(500, 听通知的人())
        await sub.subscribe_data_change(temp)               # 然后订阅:以后变了自动通知我
        await asyncio.sleep(15)                             # 挂 15 秒,看推送刷屏

asyncio.run(main())

你会看到:先打印一次读数,然后每 2 秒自动蹦一行新温度——客户端没有反复去问,是服务器主动推的。这就是"订阅推送",和 Modbus 的"点名追问"最本质的区别。(开头若出现一行 Requested session timeout… 英文提示,无视即可,只是服务器调整了超时参数。)

人话总结:OPC UA = 自带目录说明书 + 全程加密锁 + 变化才汇报。功能最强,但也最"重"(设备要跑完整的协议栈),所以它主要出现在 PLC、高端设备和车间监控软件之间。

5. 三个协议怎么配合?

一张简化对比 + 一条黄金学习路线。

问的问题ModbusMQTTOPC UA
怎么对话?老师点名,一问一答往频道扔消息,谁听谁收订阅了就主动推给你
设备会自我介绍吗?不会,翻说明书不会,靠约定会,自带目录
安全吗?裸奔有锁(TLS+密码)最全(证书+加密+权限)
消耗资源?极小,单片机能跑很小大,设备要够强
典型在哪见?电表、传感器 → 网关网关 → 云平台PLC ↔ 监控/管理软件

黄金学习路线:MQTT(概念最少,先建立信心)→ Modbus(理解"设备=柜子+抽屉")→ OPC UA(理解"自我介绍+订阅推送")。每个都用本文的动手实验跑一遍,比读十篇教程都管用。

6. 动手环境清单

一次性准备,三个实验全够用。

要装的东西

  • Docker Desktop(跑 MQTT 电台用)——官网下载安装即可
  • Python 3.10+(跑 Modbus / OPC UA 实验)——安装时勾选 "Add to PATH"
  • 两个 Python 库,终端里各执行一次:pip install pymodbus asyncua

启动 MQTT 电台(只需一次)

先在一个文件夹里新建文件 mosquitto.conf,内容只有两行:

listener 1883
allow_anonymous true

然后在该文件夹打开终端执行(把路径换成你自己的):

docker run -d --name mosquitto -p 1883:1883 ^
  -v "你的路径/mosquitto.conf:/mosquitto/config/mosquitto.conf" ^
  eclipse-mosquitto

看到一长串字符就是成功了。重启电脑后电台不会自动开,执行 docker start mosquitto 即可。
