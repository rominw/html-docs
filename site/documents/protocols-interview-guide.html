1. 面试官怎么考、你怎么答

先看清剧本,再背台词。

考察形式出现场景应对要点
八股问答几乎必有,5-10 分钟连发一句话结论 → 机制展开 → 延伸一个坑;卡壳即出局,背熟第 2-5 节
场景设计题中高级岗、二面分层作答:采集层 → 传输层 → 平台层 → 细节(断网续传/安全);模板见第 6 节
项目深挖简历写了协议经历写了"熟悉"就要能讲出细节:报文、参数、踩的坑;没做过别硬编
笔试/实操少数公司抓包读报文、写简单客户端/CRC;本专栏第 1、3 册的实验全覆盖

答题万能结构:①一句话结论(展示果断)→ ②机制展开(展示理解)→ ③"我实际验证过,当时现象是 XX"(展示上手)→ ④延伸一个坑或选型考量(展示深度)。第 ③ 步是与背题候选人拉开差距的关键——而你的实验素材,第 7 节全部整理好了。

2. 网络基础 10 题(TCP / UDP / HTTP)

所有协议岗的共同前置考点,答错会连累后面所有印象分。

题目答案要点
① 三次握手为什么不能是两次?让双方确认彼此收发能力;防历史重复 SYN 建立无效连接(第三次 ACK 可否决)。
② 挥手为什么四次?全双工,两方向独立关;被动方收到 FIN 时可能还有数据没发完,ACK 与 FIN 分开发。
③ TIME_WAIT 是什么?为什么等 2MSL?主动关闭方最后的等待:保证最后的 ACK 丢失可重传;让旧连接残留报文自然消亡。海量短连接会堆端口耗尽 → 物联网用长连接。
④ TCP 靠什么可靠?序号+确认、超时重传、滑动窗口(流量控制)、拥塞控制——四件套一个不能少。
⑤ 什么是粘包?怎么解决?TCP 是无边界字节流,多次发送可能一次到达;应用层三种切帧:定长 / 分隔符 / 长度前缀(顺势带出 MQTT 剩余长度、Modbus MBAP)。
⑥ TCP vs UDP 怎么选?要可靠有序用 TCP;要低延迟(音视频)、一对多(多播)、超轻量(DNS)用 UDP;物联网例:MQTT-SN、OPC UA PubSub 走 UDP。
⑦ 从输入网址到页面显示发生了什么?DNS 解析 → TCP 三次握手 → (HTTPS 再 TLS 握手)→ HTTP 请求响应 → 浏览器渲染;考查全局视野,按序说清即可。
⑧ HTTPS 握手做了什么?证书验证(防冒充)+ 非对称交换对称密钥 + 之后对称加密通信;与 OPC UA SecureChannel 同思想。
⑨ HTTP 1.1 / 2 / 3 一句话演进?1.1 keep-alive 长连接;2 二进制分帧多路复用;3 弃 TCP 用 QUIC(UDP 上重建可靠),解决队头阻塞。
⑩ 设备在内网,平台怎么下发指令?NAT 后设备无公网地址,平台无法直入;设备主动出连(Broker/服务器)保持长连接,下行复用该连接。

3. MQTT 12 题(平台 / 物联网岗重点)

按被问概率排序,QoS 和遗嘱几乎必考。

题目答案要点
① MQTT 和 HTTP 的区别?为什么物联网选 MQTT?发布订阅 vs 请求响应;固定头 2 字节 vs 数百字节;长连接服务端可推;弱网省电。补一句"HTTP 也不排斥,平台 API 层仍在用"更显成熟。
② QoS 三个等级?0 至多一次(发完就忘);1 至少一次(PUBACK,ACK 丢失重发 → 可能重复);2 恰好一次(PUBREC 记账→PUBREL 放行→PUBCOMP 清状态,双方状态表去重)。
③ QoS 1 为什么会重复?QoS 2 为什么四步?接收方无法区分"新消息"与"ACK 丢失后的重发";四步把"确认收到"与"允许投递"拆开,任何一步丢包都可安全重走,接收方按 PacketID 去重。
④ 设备断电,云端怎么立刻知道?遗嘱消息(LWT):连接时预登记,Broker 判定异常掉线(TCP 断开或 1.5 倍 KeepAlive 超时)后台发;注意 will 也要 retain=True。
⑤ 新订阅者怎么拿到最新值?保留消息:Broker 存每主题最后一条,订阅即推;适合开关/状态类。
⑥ 通配符 + 和 # 区别?+ 精确匹配单层(factory/+/temp 是 3 层模式,4 层 topic 不匹配);# 匹配当前层及以下全部,只能放末尾。
⑦ CleanSession 什么作用?=1 断开即焚订阅与消息;=0 持久会话,Broker 攒离线 QoS≥1 消息,重连补发(离线消息队列);5.0 换成 Session Expiry Interval。
⑧ 3.1.1 与 5.0 区别?原因码、共享订阅、消息过期、主题别名、流控、请求/响应——说满三个即达标。
⑨ 共享订阅是什么?解决什么?$share/g/topic 组内负载均衡,消息只投组内一个消费者;解决多后端实例重复消费。
⑩ 百万连接架构?EMQX 集群+LB;Topic 分层规划+ACL 前缀授权;TLS+设备证书;共享订阅横向扩后端;核心链路 EMQX→Kafka→时序库→看板。
⑪ 消息积压怎么办?共享订阅加消费者;消费端按 messageId/业务键幂等去重;非关键流降 QoS;评估调小发布间隔。
⑫ MQTT 安全?8883 TLS、每设备 X.509、ACL 主题授权、禁匿名;生产 Broker 必配。

4. Modbus 10 题(上位机 / 采集岗重点)

考察核心:背得出寄存器模型,讲得出现场的坑。

题目答案要点
① RTU 和 TCP 区别?帧结构:MBAP 7 字节头替代从站地址+CRC;TCP 事务 ID 支持多主并发,RTU 串口单主轮询;RTU 靠 3.5 字符静默切帧,TCP 靠长度字段。
② 四种寄存器?线圈(1位读写)/离散输入(1位只读)/输入寄存器(16位只读,测量值)/保持寄存器(16位读写,设定值)。
③ 常用功能码?01/02/03/04 读四类;05 写单线圈,06 写单寄存器,0F/10 批量写;03 与 04 最常用。
④ 异常响应?功能码+0x80,异常码 01 非法功能 / 02 非法地址 / 03 非法数据 / 04 从站故障。
⑤ 怎么读 32 位浮点?占两个连续寄存器,主站拼接;字节序 ABCD/CDAB/BADC 厂商不统一,必须按手册配或做成可配置。
⑥ 40001 和地址 0 什么关系?文档 1-based 惯例 vs 协议 0-based;换算 = 文档地址−类型基数(40001→0);拿到手册先确认基准。
⑦ 从站能主动上报吗?不能,纯主从问答;所以数据变化要等轮询周期 → 引出 OPC UA 订阅 / MQTT 上报的演进动因。
⑧ 500 个点怎么优化采集?连续地址批量读(FC03 一次最多 125 寄存器);按从站分组分线程;慢设备独立超时;只轮询变化频繁的,慢变量拉长周期。
⑨ Modbus 和 RS-485 什么关系?应用层协议 vs 物理总线;Modbus RTU 是"语言",485 是"公路";同理 Modbus TCP 跑在以太网上。
⑩ CRC 校验?RTU 帧尾 2 字节,CRC16 多项式 0xA001、初值 0xFFFF、低字节在前发送;能补一句"pymodbus 返回的是交换后的传输序"直接封神。

5. OPC UA 8 题(中高端岗、MES/SCADA 方向)

题少而深,核心是把"语义+安全+订阅"三张牌打全。

题目答案要点
① OPC UA 和 Modbus 本质区别?自描述语义(地址空间/信息模型,类型单位量程自带)+ 内建安全(SecureChannel/证书/权限)+ 订阅推送;Modbus 三者皆无。
② 和 MQTT 区别?怎么选?C/S+订阅推送 vs Broker 发布订阅;有语义 vs 无语义;控制系统局域网 vs 广域网上云;常配合用(UA over MQTT / 网关转换)。
③ 地址空间是什么?节点按引用连成的带类型图;8 种 NodeClass(Object/Variable/Method/ObjectType…);NodeId=命名空间+标识符,ns=0 为标准命名空间。
④ 订阅机制?Subscription→MonitoredItem→DataChangeNotification;采样间隔+死区+队列;通知带序号可重传;变化才推,毫秒级,对比轮询省带宽。
⑤ Read 和订阅怎么选?低频配置类 Read;高频变化数据订阅;混用是常态。
⑥ 安全机制?五层:SecureChannel 加密签名 → X.509 双向认证 → 用户认证(匿名/账号/证书)→ 节点级授权;生产禁 None 策略;证书管理是企业落地最大成本。
⑦ OPC DA 和 UA?DA 基于 Windows COM/DCOM 时代,配置噩梦、无安全;UA 2008 跨平台重造,IEC 62541。
⑧ PubSub 听说过吗?Part 14(2015):发布订阅扩展,走 UDP 多播(TSN 场景)或 MQTT;答出"UA over MQTT 是语义×云连接的联姻趋势"加分。

6. 场景设计题 5 道(分层作答模板)

这类题不听"标准答案",听你脑子里有没有一张分层地图。

题目答题抓手
① 工厂 300 台旧电表(Modbus)+ 20 台新 PLC(OPC UA)做能耗平台经典双协议混合:电表分总线+网关批量轮询;PLC 订阅;统一 MQTT 上云;时序库按能耗分时统计。
② 10 万台设备上报,峰值消息风暴EMQX 集群+连接 LB;共享订阅分摊;Kafka 削峰;非关键数据 QoS0+采样聚合(网关侧预聚合再传)。
③ 弱网(4G/卫星)环境数据不丢QoS1+消费端幂等;网关本地缓存断点续传;遗嘱感知离线;时钟对齐+补采机制。
④ 平台要反向控制车间设备下行 Topic 权限隔离;指令带回执(响应主题+关联数据);关键动作用 QoS2;PLC 侧安全联锁不依赖网络。
⑤ 三个协议你都会,为什么这个项目选 X?按分层定位回答(现场/控制/广域),再谈团队能力与设备现状;展现"没有银弹"的工程观。

7. 把动手实验包装成项目经验

你真实跑过的九组实验,每条都能变成面试桌上的"实证素材"。

实验经历支撑的面试题(话术示例)
Docker 部署 Mosquitto,配置监听与匿名开关"我部署过 Mosquitto,知道生产要关匿名、上 TLS 与证书——本地实验时我特意验证过匿名开关的行为。"
双终端命令行收发 + 通配符匹配验证"我验证过 + 的单层语义:4 层主题不匹配 3 层过滤器,现场 Topic 规划时踩过这个坑。"
强杀进程触发遗嘱,秒级收到 offline"遗嘱我实测过:进程被强杀,订阅端同一秒收到 offline;还发现 will 不带 retain 会导致快照过期。"
开 paho 日志观测 QoS 交互"我抓过 QoS2 的交互:收到 PUBREC 前客户端绝不会发 PUBREL,四步握手状态机一目了然。"
裸 socket 手拼 MQTT 报文"我用纯 socket 拼过 CONNECT/PUBLISH,剩余长度变长编码是手写的——MQTT 对我就是这些字节。"
手写 CRC16 并与 pymodbus 对账"CRC 我手写过,还发现 pymodbus 返回的是交换后的传输序——两库对接时字节序约定要先对齐。"
模拟从站+主站读写、异常响应实测"异常响应我实测到 function_code=131(03+0x80)、异常码 02,不是背的。"
裸 socket pipelining+粘包切帧"粘包我用两条连发请求复现过,靠 MBAP 长度字段切帧、事务 ID 配对,和 MQTT 剩余长度是同一类设计。"
OPC UA 服务器+订阅推送实测"订阅推送我跑过:客户端零轮询,服务器值变化毫秒级通知——修过一版忘了 server.start() 的示例,连不上时靠端口排查定位。"

诚信红线:话术只放大真实经历,不虚构没做过的东西。面试官追问"你那个 Broker 集群怎么部署的"而实验只是单机,就如实说"单机验证过功能,集群方案我了解原理但没实操"——诚实+知道边界,比吹破皮安全得多。
