1. 术语正名:从比喻到官方表达

入门篇用比喻建立直觉,这一步把直觉钉在规范术语上——面试、看文档、和同行对话,都用右边这列。

入门比喻官方术语规范中的一句话定义
广播电台Broker(代理服务器)接收所有发布消息,按订阅关系分发的中心实体(MQTT)
寄信 / 调频道Publish / Subscribe客户端向 Broker 发消息 / 向 Broker 注册 Topic 过滤器
频道标签Topic(主题)分层字符串(如 factory/line1/temp),Broker 路由的依据;+ 单层、# 多层通配
老师点名主从模型 Master/Slave仅 Master 发起请求,Slave 被动应答;新版规范改称 Client/Server,现场口语仍是主从(Modbus)
挨个问一遍轮询 Polling主站按周期依次读取各从站数据
四个抽屉数据模型(四类寄存器)Coil 线圈(1位读写)/ Discrete Input 离散输入(1位只读)/ Input Register 输入寄存器(16位只读)/ Holding Register 保持寄存器(16位读写)
"读 3 号抽屉"功能码 Function Code请求 PDU 首字节,规定动作:01/02/03/04 读,05/06/0F/10 写
"答不了"异常响应 Exception Response功能码 +0x80,附异常码 01~04(非法功能/地址/数据/从站故障)
自我介绍的目录树地址空间 Address Space / 信息模型 Information Model节点(Node)按引用(Reference)连成的图,自带类型与元数据(OPC UA)
设备的名片NodeClass / NodeId节点类别(Object/Variable/Method 等 8 种)与全局唯一标识(ns 索引 + 标识符)
变了才汇报Subscription / MonitoredItem / DataChange Notification客户端登记监视项,服务端值变化时主动推送,带序号可重传
接头暗号SecureChannel + X.509 双向认证应用层加密通道 + 应用/用户两层身份验证(OPC UA 安全五层)

用法建议:和同行沟通时先说官方术语、再用比喻解释——"我们用共享订阅做后端负载均衡,就是一个频道多个收音机轮流接单"。术语给人专业信号,比喻保证不掉沟通效率。

2. 协议的版本与类型体系

"协议类型"其实是三个维度:跑在什么传输上、规范演进到哪一代、归哪个组织管。

2.1 先分清层次:它们都是应用层协议

三个协议都不关心网线里怎么传字节(那是 TCP/UDP 传输层的事),只规定消息的含义与交互规则。所以每个协议都衍生出"跑在不同传输上"的变体,这是第一个维度:

协议传输变体说明
MQTTTCP(1883 / TLS 8883)标准形态,绝大多数设备用这个
MQTT over WebSocket(8083)浏览器 / 受限网络环境直连 Broker
MQTT-SN(Sensor Networks)UDP 版,给跑不动 TCP 栈的超弱传感器;经网关转标准 MQTT
ModbusRTU(串口 RS-232/485)二进制帧 + CRC16,现场主流
ASCII(串口)文本帧 + LRC 校验,体积翻倍,基本淘汰
Modbus TCP(默认 502)MBAP 头替代地址与 CRC,多主并发
OPC UAopc.tcp://(二进制)标准形态,自带 SecureChannel
HTTPS + XML(WS-*)历史遗留,已废弃
PubSub(Part 14)UDP 多播 / 原始以太网(TSN)/ 经 MQTT 中转

野生变体警告:现场还有一种"Modbus RTU over TCP"——把串口帧原样塞进 TCP,私有非标。接网关设备时务必确认是标准 Modbus TCP 还是 RTU over TCP,连错了神仙也调不通。

2.2 第二维度:规范版本演进

协议版本线关键差异现场主流
MQTT3.1 → 3.1.1(2014,OASIS)→ 5.0(2019)5.0 新增:原因码、消息过期、主题别名、共享订阅、流控、请求/响应3.1.1 仍占多数;5.0 渗透中,EMQX 全支持
Modbus1979 原版 → 1997 TCP → 2007 OASIS 标准化四十年几乎没变——不升级正是它遍地都是的原因;免费无专利只有一版,无兼容包袱
OPC UA2008 1.0 → 持续演进(IEC 62541,共 14 个 Part)Part 14 = PubSub(2015);近年热点:FX(云交互)、over TSN(实时以太网)1.03/1.04 并存;选型看配套规范支持

2.3 第三个维度:谁管标准

MQTT → OASIS

结构化信息标准促进组织,与 AMQP 同门;规范全文公开可下载。

Modbus → Modbus Organization

厂商中立组织,协议免费开放;注册即可使用商标。

OPC UA → OPC 基金会 + IEC

工业自动化厂商联盟维护,同时是国际标准 IEC 62541——面试说出这个编号即是加分。

3. 企业真实架构:ISA-95 分层与三协议同框

ISA-95 是企业集成的官方地图——知道每层是什么、三个协议各自守哪层,架构讨论就有了坐标系。

读图要点:左边"楼梯"是传统 IT/OT 分层,OPC UA 守 1~3 层(控制到执行的垂直集成);右边"旁路"是物联网时代新增的云端通道,MQTT 负责"设备/网关 → 云"的广域传输。两条通道并行,不冲突——这正是三个协议同框的原因。

4. MQTT 企业实战:平台级玩法

从"能收发"到"支撑百万设备",差的是平台工程这一层。

Broker 选型梯队

  • EMQX:国产主力,单机百万连接、集群、规则引擎、Web 控制台,自建首选
  • Mosquitto:C 语言轻量标杆,边缘网关 / 工控机首选
  • 云托管:AWS IoT Core、阿里云 IoT 企业版、华为 IoTDA——免运维按量计费

企业级三件套

  • Topic 纪律:统一模板 租户/工厂/产线/设备/测点,权限(ACL)按前缀授权;乱起 Topic 是平台事故头号来源
  • 共享订阅:$share/group/factory/# 让 N 个后端实例分摊消息(消费组思想)
  • 安全:TLS + 每设备一张 X.509 证书,杜绝匿名接入

SparkPlug B:给 MQTT 补语义

  • 标准 MQTT 没有语义(Topic 约定而已),SparkPlug B 补上设备上下线(出生/死亡证书)、数据模型、状态管理
  • 欧美工业界大量采用;国内更多自定义 JSON 约定——对接前先问对方"用不用 SparkPlug"
  • 参考实现:Eclipse Tahu

下游标准链路

  • EMQX 规则引擎 → Kafka(数据总线)→ 时序数据库(TDengine / InfluxDB)→ Grafana 看板
  • 这条流水线是物联网后端的事实标准架构,面试可整段说出

5. Modbus 企业实战:采集层的日常

企业的 Modbus 工作不在写协议,而在"点表、网关、现场调试"三件事。

硬件链路

RS-485 手拉手布线(两端 120Ω 终端电阻)→ DTU(串口转 4G/网口)→ 边缘网关(映翰通、有人、Moxa、摩尔)。网关干的活就是"南向 Modbus 采集、北向 MQTT 上云"。

商业中间件

KepServerEX(PTC)是业界事实标准:南向支持 Modbus / 西门子 / 三菱等上百种驱动,北向统一输出 OPC UA——一次配置全厂可用;国产替代 KingIOServer 等。

点表工作法

每台设备一份寄存器地址表(40001 温度…),采集系统按表轮询。老师傅三板斧:批量读(多个寄存器一次读完)、字节序开关(32 位浮点 ABCD/CDAB 各厂不同)、超时重试。

坑症状解法
文档 1-based vs 协议 0-based读出来永远是 0 或错位拿到手册先确认寻址基准,换算 = 文档地址 − 类型基数
从站响应慢(100ms+)轮询周期被拖垮、超时频发合并读请求、拉长单站超时、并发多线程分片轮询
485 总线干扰偶发 CRC 错、数据跳变手拉手拓扑、终端电阻、屏蔽线单点接地、远离变频器
32 位值字节序浮点读出天文数字采集端按手册配置 ABCD/CDAB/BADC 重排,留成可配置项

6. OPC UA 企业实战:高端集成的通用语

它的价值在企业里才 fully 兑现:自带语义让"接入成本"大幅下降,自带安全让 IT 部门放心。

服务器从哪来、谁消费

  • 新版 PLC 自带 OPC UA Server:西门子 S7-1500、倍福、罗克韦尔全系
  • 老设备经 KepServerEX 包装成 OPC UA(南向 Modbus → 北向 UA)
  • 消费方:SCADA(Ignition、WinCC OA)、MES、数据平台——因为自描述,接入远快于挨个配点表

配套规范与工具

  • 行业语义:PLCopen(运动控制)、PackML(包装机状态机)、Euromap(塑机);汽车 / 制药行业常强制要求
  • 调试必备:UA Expert(免费客户端,浏览任意服务器地址空间,相当于浏览器 DevTools)
  • 建模工具:UA Modeler

落地最大成本是证书管理:双向认证要求每个客户端/服务端各持证书并互信,企业需建内部 CA 统一发证;设备换件要重新授权。安全不是开关,是有运维成本的制度——立项时就要算进去。

7. 岗位视角与继续深入

三个协议对应五类岗位,每类的"主武器"不同。

岗位主用协议典型技术栈进阶方向
上位机 / SCADA 开发Modbus + OPC UAC# / .NET WPF、Qt配套规范、工业 GUI
边缘网关开发三者全用Go / Java / C,协议解析高并发采集、断点续传
物联网平台开发MQTT 为主EMQX 插件、Kafka、时序库规则引擎、海量连接
数据采集 / 现场实施Modbus 为主点表配置、串口抓包多种行业规约(DL/T 645 等)
MES / 工业软件集成OPC UA 为主Kepware、配套规范ISA-95 / 数字孪生

继续深入的顺序建议:① 把入门篇的本地实验全部跑熟;② 挑主线岗位对应的协议读官方规范(MQTT 3.1.1 中文译本最好读、Modbus 规范仅几十页、OPC UA 先读 Part 1 概念);③ 装一次真实中间件(EMQX 单机版或 UA Expert 连演示服务器)补全体感;④ 关注 SparkPlug B 与 OPC UA FX 两个演进热点,面试聊趋势加分。
