1. 按技术类别，回到项目机制

把简历里的技术名词变成能解释、能推演、能验证的链路。

选题依据

以用户提供简历中的技能与项目描述确定类别，只整理技术与泛化场景，不发布个人资料。Java、服务框架、数据、事件、工作流、Agent、前端、视觉和部署均有对应入口。

深度标准

每个主题按“关键词—结论—机制—失效窗口—追问—验证”展开。先把状态和执行者说清，再讨论保证范围与反例，避免名词清单式复习。

事实边界

简历负责选题，官方资料用于核对机制，项目例子用于教学推演。本文不替代项目源码审计，也不把示例方案或自检描述为已在生产实现。

4. 四条项目线索，练习跨类别推演

下面是泛化教学场景，不是对真实实现和线上效果的断言。

多机库调度：谁获得执行资格？

Java、JVM 与并发 → Spring 与服务工程 → MySQL 与 Elasticsearch → Redis 与分布式一致性 → Kafka、RabbitMQ 与事件驱动 → Temporal 与持久工作流

区域与配置用版本快照；并行规划有预算；资源占用用权威条件；父任务按唯一子任务聚合。推演“旧锁持有者恢复”“部分占用成功”“完成事件重送”，分别回答谁拒绝旧资格、谁释放资源和谁查证设备结果。

记忆关键词：快照 · 准入 · 资格 · 子任务身份 · 聚合 · 未知查证

业务智能体：模型建议如何成为可审计的 Action？

LLM、Agent 与工具协议 → Vue、TypeScript 与流式通信 → Redis 与分布式一致性 → MySQL 与 Elasticsearch → K8S、可观测性与工程交付

Channel 关联可信会话；查询工具受权限保护；执行绑定确定动作、资源与确认快照；终态保护和 SSE 只是各自一层保证。推演“同键异参”“确认后资源变化”“设备成功但回包丢失”，解释页面和后端各自应该显示什么。

记忆关键词：可信主体 · 意图校验 · 确认绑定 · 稳定身份 · 终态 · 恢复

多轮复核：循环为何终止，发版为何仍可恢复？

Temporal 与持久工作流 → Python 与视觉 AI 工程 → MySQL 与 Elasticsearch → Kafka、RabbitMQ 与事件驱动

区分有效观测与未知结果；按可靠对象身份划分新增与复现；总预算限制持续新增。推演“旧轮次回调迟到”“观测失败却当空集合”“版本桩过早删除”，给出收敛理由、历史兼容和查证证据。

记忆关键词：有效观测 · 集合变化 · 身份 · 预算 · marker · 回放

大屏与视觉统计：哪个数字代表哪个时刻的事实？

Python 与视觉 AI 工程 → MySQL 与 Elasticsearch → Redis 与分布式一致性 → Kafka、RabbitMQ 与事件驱动 → K8S、可观测性与工程交付

YOLO 候选、SAM 掩膜、VLM 复核与跨图去重有不同指标；数据库事实、ES 搜索与缓存又有不同可见时间。推演“坐标偏移”“分片候选截断”“旧缓存回填”，说明版本、数据时刻、误差与权限口径。

记忆关键词：坐标契约 · 条件概率 · 对象身份 · 分片候选 · 版本 · 口径

5. 把原理转成自己的回答与证据

先交代真实职责，再说机制和失败窗口；不要把教学方案当个人成果。

回答层次要讲清什么自检方式
职责负责、主导、参与的范围分别是什么能指出自己改动的模块、接口和决策
机制状态在哪里、谁执行、哪个操作是原子的画时序并解释每个确认
边界重复、乱序、超时、过期与进程退出会留下什么提出一个能推翻笼统结论的交错
证据源码、版本、日志、测试和实验分别证明什么不把模型自检说成真实集群/SDK验证
取舍为什么采用当前方案，还有哪些限制从约束与代价推导，不背技术优劣排名

统一复述顺序：“业务约束 → 机制与数据流 → 保证范围 → 失败反例 → 验证证据”。关键词用来找回论证，不能替代原理。
