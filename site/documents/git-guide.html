Git 日常操作指南

从第一次配置，到提交、同步、分支协作和安全撤销。目标不是背命令， 而是建立一套不容易出错的工作节奏。

目录 先理解四个区域 首次配置 日常提交流程 同步远程更新 使用分支协作 安全撤销 忽略文件 常见问题 本站发布示例 速查表

先理解四个区域

Git 的大多数命令，只是在四个区域之间移动内容。理解这条路径后， add、commit 和 push 就不再是一串需要死记的咒语。

工作区正在编辑的文件
暂存区准备提交的内容
本地仓库已经创建的提交
远程仓库GitHub 等服务器

git add 把改动放入暂存区，git commit 把暂存内容保存为本地提交，git push 再把提交发送到远程仓库。

首次配置

安装 Git 后，先设置提交记录中显示的姓名和邮箱。这通常只需执行一次。

git config --global user.name "你的名字"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

# 检查当前配置
git config --global --list

克隆已有项目

git clone https://github.com/owner/project.git
cd project

把普通文件夹变成仓库

cd your-project
git init
git add .
git commit -m "Initial commit"

日常提交流程

每次准备提交时，建议坚持“查看—选择—复查—提交—推送”的顺序。

# 1. 查看改了什么
git status
git diff

# 2. 选择要进入本次提交的文件
git add path/to/file

# 3. 复查已经暂存的内容
git diff --staged

# 4. 创建本地提交
git commit -m "Add search to document list"

# 5. 推送到远程仓库
git push
一次提交只做一件事 功能、重构和格式化尽量分开提交。这样历史更清晰，撤销时也更安全。

怎样写提交信息

推荐原因
Add article search说明新增了什么能力
Fix mobile navigation说明修复对象
Update deployment guide说明更新范围
修改一下过于含糊，日后无法快速理解

同步远程更新

开始工作前先同步，可以减少冲突。fetch 只下载远程信息， 不修改当前文件；pull 则会下载并整合到当前分支。 

# 查看远程仓库
git remote -v

# 下载远程状态，但暂不合并
git fetch origin

# 拉取并合并当前分支
git pull

# 保持提交历史更线性
git pull --rebase
本地还有未提交修改时，不要急着 pull 先提交改动，或者用 git stash 临时收起，再进行同步。 
git stash push -m "临时保存"
git pull --rebase
git stash pop

使用分支协作

分支让新功能与稳定版本互不干扰。通常从最新的主分支创建功能分支， 完成后推送并发起 Pull Request。 

# 从主分支开始
git switch master
git pull --rebase

# 创建并切换到功能分支
git switch -c feature/git-guide

# 完成修改后提交并首次推送
git add site/documents/git-guide.html
git commit -m "Add Git operations guide"
git push -u origin feature/git-guide

合并完成后，可以清理本地分支： 

git switch master
git pull
git branch -d feature/git-guide

安全撤销

先判断改动位于哪个区域，再选择相应命令。

目标命令
撤销工作区中某个文件的修改 git restore path/to/file
把文件移出暂存区，保留修改 git restore --staged path/to/file
修改最近一次提交信息 git commit --amend
撤销一个已经推送的提交 git revert <commit>
找回误删分支或提交 git reflog
谨慎使用 reset --hard 和强制推送 它们可能永久丢弃未保存内容或改写共享历史。多人协作时，优先使用 git revert 创建一个可追踪的反向提交。

忽略不应提交的文件

在仓库根目录建立 .gitignore，排除依赖、缓存、构建产物 和本地密钥。已经被 Git 跟踪的文件，不会因为后来加入忽略规则而自动消失。 

# 依赖与缓存
node_modules/
.cache/

# 本地环境变量
.env
.env.*

# 系统和编辑器文件
.DS_Store
.vscode/

# 构建产物
dist/

如果文件已经被跟踪，可用 git rm --cached path/to/file 停止跟踪，但保留本地文件。 提交前务必确认其中没有密码、令牌或私钥。

常见问题

推送被拒绝：远程包含本地没有的提交

git pull --rebase
# 如有冲突，解决后：
git add path/to/resolved-file
git rebase --continue
git push

不确定自己在哪个分支

git branch --show-current
git status

提交到了错误分支，但还没有推送

# 在当前提交处创建正确分支
git switch -c correct-branch

# 回到原分支，再恢复它原本的位置
git switch original-branch
git reset --keep HEAD~1

发生合并冲突

打开冲突文件，寻找 <<<<<<<、 ======= 和 >>>>>>> 标记， 手动保留正确内容并删除标记，然后执行 git add 和 git commit。不确定时先备份当前文件。

本站的实际发布流程

本站由 Cloudflare Pages 托管。把完整 HTML 文件放入 site/documents，生成首页索引并推送到 master，Cloudflare 就会自动构建和发布。 

git pull --rebase

# 添加文章后生成 site/documents.json
npm run build

# 检查、提交、推送
git status
git add site/documents/git-guide.html site/documents.json
git commit -m "Add Git operations guide"
git push origin master
  • 文章包含唯一且准确的 <title>
  • 文章包含用于首页展示的 description
  • <time datetime="YYYY-MM-DD"> 日期有效
  • npm run build 正常完成
  • git status 只包含预期文件

一分钟速查表

git status                 # 查看当前状态
git diff                   # 查看未暂存修改
git diff --staged          # 查看已暂存修改
git add <file>             # 暂存指定文件
git commit -m "Message"    # 创建提交
git pull --rebase          # 同步远程提交
git push                   # 推送当前分支
git switch -c <branch>     # 新建并切换分支
git log --oneline --graph  # 查看精简历史
git restore <file>         # 丢弃未暂存修改
git revert <commit>        # 安全撤销已发布提交
最重要的习惯 提交前看 status 和 diff；推送前读一遍提交信息。 多花十秒复查，通常能省下半小时排错。
